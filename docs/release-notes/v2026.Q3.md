# OSSCAR v2026.Q3

This release covers **Q3 2026**, the inclusive calendar interval from July 1
through September 30. The scoring and chart window contains the Sunday buckets
from July 5 through September 27.

Two organization websites were corrected after publication because the

The full ranking contains 56,079 organizations: 40,648 emerging and 15,431
scaling. The website publishes the top 100 in each division and keeps the
complete quarter in the app-facing database for organization score requests.

## Methodology changes

Q3 uses methodology **v9**. Relative to the Q2 release:

- each signal's growth is capped at its 99.9th percentile within the division
  before log-minmax scaling, so a single extreme organization no longer sets
  the scale for everyone else; equal capped scores are ordered by the uncapped
  score, and displayed growth rates are never capped;
- GitHub stars are the active stock net of removed stars (`stars_total`), so a
  star count can decline;
- every repository that existed before the quarter needs a star measurement at
  the quarter start, or the organization is not ranked that quarter;
  repositories GitHub no longer resolves are left out of star counts;
- a package linked to several repositories of one organization counts once;
- forks and archived repositories are excluded from every signal.

The division threshold, three signals, padding thresholds, and L² composite
are unchanged. See the complete [methodology](../methodology.md) and
[data collection](../data-collection.md) notes.

## Reproduce the ranking

Check out the release tag and use the pinned dependencies:

```bash
git checkout v2026.Q3
python -m pip install -r methodology/requirements.txt
python methodology/compute_index.py \
  --input methodology/data/osscar_input_data_Q3_2026.parquet
```

The output is `methodology/results/osscar_ranking_Q3_2026.parquet` and matches
the ranking checksum above.

## Known limitations

- Star weeks before August 2026 are reconstructed from GitHub's history of
  stars that are still active, so stars removed since then are missing from
  those weeks.
- The index does not detect or exclude inauthentic activity such as bought
  stars, classroom repositories, or packages that are always installed
  together.
- Package downloads cover npm, PyPI, and Cargo; organizations centered on
  other registries are ranked on the signals available to OSSCAR.
- Weekly calendar buckets do not split partial boundary weeks into daily
  estimates.
- OSSCAR measures one quarter of momentum, not the long-term importance of a
  project.
