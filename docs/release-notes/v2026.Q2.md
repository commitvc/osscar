# OSSCAR v2026.Q2

This release covers **Q2 2026**, the inclusive calendar interval from April 1
through June 30. The scoring and chart window contains the Sunday buckets from
April 5 through June 28.

## What's in this release

| Asset | Description | SHA-256 |
|---|---|---|
| `osscar_input_data_Q2_2026.parquet` | Raw per-organization metrics consumed by the scoring pipeline | `1debfe05aadb6bc4f5c521ed70370116954e5d222d00c829a6db74b01a32fb54` |
| `osscar_ranking_Q2_2026.parquet` | Input columns plus division, rank, and derived scoring fields | `c44da0d0a6ff41012c9fd3f59521bc293881d5d677032b48fa22c475c23e14e4` |
| `SHA256SUMS.txt` | Checksums for both Parquet assets | — |

The full ranking contains 48,799 organizations. The website publishes the top
100 in each division and keeps the complete quarter in the app-facing database
for organization score requests.

## Methodology changes

Q2 uses methodology **v8**. Relative to the Q1 release:

- scalar start/end values, score inputs, and charts now share the exact first
  and last retained weekly buckets;
- the published real growth rate stays null when the observed start is zero,
  while the padded baseline still permits fair ranking;
- the website displays the padded ranking multiplier and explicitly discloses
  observed chart endpoints when they differ.

The division threshold, three signals, log-minmax normalization, padding
thresholds, and L² composite are unchanged. See the complete
[methodology](../methodology.md).

## Download and verify

```bash
gh release download v2026.Q2
shasum -a 256 -c SHA256SUMS.txt
```

## Reproduce the ranking

Check out the release tag and use the pinned dependencies:

```bash
git checkout v2026.Q2
python -m pip install -r methodology/requirements.txt
python methodology/compute_index.py \
  --input methodology/data/osscar_input_data_Q2_2026.parquet
```

The output is `methodology/results/osscar_ranking_Q2_2026.parquet` and matches
the ranking checksum above.

## Known limitations

- Package downloads cover npm, PyPI, and Cargo; organizations centered on
  other registries are ranked on the signals available to OSSCAR.
- Weekly calendar buckets do not split partial boundary weeks into daily
  estimates.
- OSSCAR measures one quarter of momentum, not the long-term importance of a
  project.
